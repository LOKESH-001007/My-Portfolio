Overview

What this project is

Course Management Portal is a web application that lets students browse and enroll in courses, and lets admins create, edit, and manage the course catalog. It started as a Java Servlet + JSP + raw JDBC project, and I rebuilt it end-to-end in Spring Boot — swapping hand-written SQL for Spring Data JPA, a custom session filter for Spring Security, and JSP templates for Thymeleaf — while keeping every original feature intact.

The Challenge

Why rebuild a working app?

THE PROBLEM

The original app worked, but every new feature meant touching a DAO class, a servlet, a JSP, and often web.xml. Manual JDBC connection handling and hand-wired dependencies made the codebase fragile and slow to extend — and it wasn't a stack most modern Java teams actually hire for.

THE SOLUTION

A full migration to Spring Boot: Spring Data JPA repositories replaced ~500 lines of DAO code with five-line interfaces, Spring Security handled dual-role authentication (student/admin) out of the box, and Thymeleaf brought server-side templating in line with how the framework actually expects it.

Features

What it does

🔐

Dual-role authentication

One login screen, two roles — Spring Security checks the Admin table first, then falls back to Students, using BCrypt-hashed passwords.

📚

Course catalog management

Admins can add, edit, and remove courses with fee, duration, trainer, and category fields — all validated server-side.

🎓

Student enrollment

Students browse active courses and enroll with one click; duplicate enrollments are blocked at the database level.

📊

Personal dashboard

Each student has a "My Courses" view pulling only their own enrollments via a scoped repository query.

🗄️

Relational data model

Four related MySQL tables — Admins, Students, Courses, Enrollments — mapped with JPA @ManyToOne relationships.

☁️

Cloud deployed

Live on Render with a custom domain and CNAME routing, connected to a managed MySQL instance.

Challenges & Learnings

What actually broke, and how I fixed it

01

Schema/entity type mismatches

Hibernate's ddl-auto=validate rejected the app on startup because fees was a Java double but the column was DECIMAL(10,2) in MySQL, and a timestamp field was typed as String instead of LocalDateTime.

→ Fixed by matching every entity field type exactly to its SQL column type — BigDecimal for money, LocalDateTime for timestamps.
02

One login form, two different user tables

Admins and Students live in separate tables with different identifying fields (username vs. email). Spring Security's default login only understands a single "username" field.

→ Solved with a custom UserDetailsService that checks the Admin table first, then falls back to Student lookup by email.
03

JSP scriptlets don't translate to Thymeleaf

Direct copy-pasting old JSP templates into the new templates/ folder produced broken pages — Thymeleaf doesn't understand <% %> scriptlets or JSP's pageContext expressions at all.

→ Rebuilt each view using Thymeleaf's own syntax (th:each, th:field, @{...}) rather than translating line-by-line.
